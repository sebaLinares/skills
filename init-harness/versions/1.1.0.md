# 1.1.0 — Explicit plan-approval gate

## What changed

The harness now defines **what counts as plan approval**, closing a loophole
where an agent treated a clarifying-question exchange as a green light and
began executing without an explicit go-ahead. Approval is now stated as
explicit and plan-scoped: answering clarifying questions, acknowledgement
("ok", "makes sense"), and silence are **not** approval. `harness.md` Phase 3
carries the full definition; `AGENTS.md` § Hard constraints carries a compact
invariant plus a pointer to it.

## How to apply

Additive guidance — fill each block in if absent. No confirmation needed.

1. In `docs/processes/harness.md`, Phase 3 — Plan: if the paragraph beginning
   "**What counts as approval.**" is absent, insert it immediately after the
   Phase 3 Gate line ("…and the user has approved it. No code before this."):

   > **What counts as approval.** Approval is explicit and plan-scoped — an
   > affirmative go-ahead on *this* plan ("approved", "go ahead", "build it",
   > "yes, implement it"). These are **not** approval: answering your clarifying
   > questions (that refines the plan, it does not authorise it); acknowledgement
   > ("ok", "makes sense", "sounds good") or silence; approval of an earlier or
   > different version of the plan. If a clarifying exchange changed the plan,
   > restate what changed and ask for approval before Execute. When unsure
   > whether you have it, ask "approve this plan?" and stop. Never infer approval
   > from engagement.

2. In `AGENTS.md`, § Hard constraints: if a bullet beginning "**MUST** treat
   plan approval as explicit and plan-scoped" is absent, add it immediately
   after the "**MUST NOT** write code without an approved ExecPlan…" bullet:

   > - **MUST** treat plan approval as explicit and plan-scoped. Answering
   >   clarifying questions, acknowledgement, or silence is **not** approval — it
   >   refines the plan, it does not authorise execution. After any clarifying
   >   exchange, restate what changed and ask for approval; then wait. Never infer
   >   approval.
   >   *(See [`docs/processes/harness.md`](docs/processes/harness.md) § Phase 3.)*

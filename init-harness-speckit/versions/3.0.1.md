# 3.0.1 — A closed-out feature can be committed

## What changed

Fixes a collision between `closeout` and the plan-coverage sensor that made
every feature's final commit unreachable. `speckit_gate.py closeout` writes
`status: completed` *before* anything is committed, while
`check_plan_coverage.py` only accepted `status: active` — so the one commit
that carries a finished feature's code was always the commit with no active
plan, and the sensor rejected it with "no active plan". Nothing in the harness
ever stated a commit-vs-closeout order, so the documented flow (`harness.md`
phase 5, § Session Exit) led straight into it; the only ways out were an
undocumented two-commit dance or `HARNESS_BYPASS` on every feature.

The sensor now also accepts a plan that **this same commit** moves from
`active` to `completed`: index says `completed`, `HEAD` says `active`. That is
precisely a closeout in flight and nothing else. A plan already `completed` in
`HEAD` still authorizes nothing, `draft` still blocks, and the "more than one
active plan" abort still fires if one plan is closing while another is active —
so the control is not weakened, only the false positive removed. Two selftest
cases pin both halves: `closing-plan-allows` and `completed-at-head-blocks`.

`docs/processes/harness.md` § Session Exit and `docs/PLANS.md` § The `covers:`
field now say the closeout edit and the work it closes belong in one commit.

## How to apply

1. **Overwrite the sensor in place** — scripts are generated, not team-edited.
   Copy `assets/scripts/check_plan_coverage.py` over
   `scripts/harness/check_plan_coverage.py`, keep it executable, then run its
   selftest and report PASS/FAIL:

       python3 scripts/harness/check_plan_coverage.py --selftest

   Expect eleven PASS lines, including the two new cases.

2. **`docs/processes/harness.md` § Session Exit, step 1** — if the sentence is
   absent, append to it: commit `closeout`'s `plan.md` edit together with the
   work it closes, since the sensor accepts a plan this same commit moves from
   `active` to `completed`.

3. **`docs/PLANS.md` § The `covers:` field** — if absent, add the same rule
   after the "staged deletes count as edits" sentence: a plan the same commit
   moves `active` → `completed` still authorizes its `covers:`; a plan already
   `completed` in `HEAD` authorizes nothing.

4. **Advance `.harness-version` to `3.0.1`.** No `doctor` invariant changed;
   `python3 scripts/harness/speckit_gate.py doctor` should report what it did
   before.

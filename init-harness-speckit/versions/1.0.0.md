# 1.0.0 — Initial release

## What changed

First release of `init-harness-speckit`: layers the harness governance layer
over a repository that **already has GitHub spec-kit installed**, based on the
`be-paris-backend-cl-ms-search` setup.

The constitution is supreme and team-owned; the harness sits beneath it as the
process layer. It edits exactly **one** spec-kit file:

- `.specify/templates/plan-template.md` — prepends harness frontmatter
  (`ticket/status/covers/verify/analyzed`) and replaces the Constitution Check
  placeholder with a gate that points at `.specify/memory/constitution.md` plus
  the two harness controls (`covers:`, `verify:`).

`.specify/memory/constitution.md` is **never touched** — it is the highest-
authority document, authored by the team via `/speckit-constitution`.

Adds alongside spec-kit (never merged into its generated files):
`.specify/extensions.yml` (five hooks), four `harness-*` hook skills canonical
in `.agents/skills/` and symlinked into `.claude/skills/`,
`scripts/harness/speckit_gate.py` + `check_plan_coverage.py` (+ optional
`wt_fanout.sh`, `tasks_to_issues.sh`), the `docs/` governance layer (PLANS,
README catalog, harness + speckit-loop + dev-setup processes, three ADRs,
tech-debt tracker, and `HARNESS-TODO.md` — a non-blocking checklist of the
skeleton files each team fills), repo-root `AGENTS.md` (+ `CLAUDE.md` symlink),
`ARCHITECTURE.md`, `SECURITY.md`, a stack-neutral `.githooks/pre-commit`, and
`.harness-version`.

Spec-kit's scripts, neutral templates, and generated `speckit-*` skills are
never touched.

## How to apply

Fresh scaffold — there is no prior version to migrate from. Requires spec-kit
already installed. Follow the scaffold steps in `SKILL.md`. A re-run on an
already-1.0.0 repo is a no-op (every step is fill-missing / idempotent
check-then-act).

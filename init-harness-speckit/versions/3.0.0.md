# 3.0.0 — The scaffold proves itself; the sensors are not exempt from the sensors

## What changed

Fixes the class of failure found by auditing the reference repo, where
`.harness-version` read `2.0.0` while the repo still carried a file that
version's delta retires and lacked a `.gitignore` entry from the 1.0.0
scaffold. The marker was written on trust and nothing ever measured it. New
`speckit_gate.py doctor` asserts the harness invariants — the five `.gitignore`
entries, the five hooks in `extensions.yml`, both `plan-template.md` edits, the
four `harness-*` skills plus their `.claude/skills/` symlinks, the absence of
files retired by earlier versions, a feature hint that resolves to an active
plan, and pre-commit wiring — and **Step 11 now refuses to write or advance
`.harness-version` until it passes**, with one recorded exception for a Step-10
YAML/JSON hook manager the skill will not auto-edit. Every version file must
now carry a **Removed** section, and each retired path must be listed in
`RETIRED_FILES` so `doctor` catches the repo that recorded a version without
applying its deletions.

Feature resolution keeps spec-kit's precedence (`SPECIFY_FEATURE_DIRECTORY` →
`.specify/feature.json` → single active plan) but now validates that the
resolved plan is still `status: active`: a stale hint falls back to the single
active plan with a warning, or fails with an explicit stale-feature message
when there is no unambiguous fallback. Previously a `feature.json` left
pointing at a completed feature silently gated it. That resolution now lives in
exactly one place — `wt_fanout.sh` calls the new `speckit_gate.py feature-dir`
instead of carrying a second bash implementation that had already drifted (it
never checked `status:`), and its `--selftest` no longer depends on `$OLDPWD`.

`scripts/harness/` is removed from the plan-coverage sensor's always-allowed
prefixes: a commit could rewrite the sensors themselves with no active plan,
which is the change that most needs one. The scaffold's own install commit is
now expected to use `HARNESS_BYPASS`, and Step 12 says so.

New `speckit_gate.py closeout` re-checks convergence (no unchecked tasks,
`verify:` green) and only then sets the plan to `status: completed`; `loop`
names it as the required final action on `stop-converged`, and `harness-loop`
runs it. Green convergence no longer leaves an active plan behind to block the
next feature.

Two rules that existed only as ADR prose are now written where an agent reads
them at the moment they apply: `AGENTS.md` gains hard constraints for skipping
`/speckit-implement`'s repo-mutating "Project Setup Verification" step and for
stopping after a `/speckit-clarify` write until the human approves the changed
scope, and `docs/processes/harness.md` gains an "Overrides of generated spec-kit
steps" table. Finally, the sanctioned lite Execute path is documented
everywhere instead of only in `AGENTS.md` — `harness.md`, `speckit-loop.md`,
and the `before_implement` hook prompt now distinguish full (`/speckit-implement`
+ `/speckit-converge`, needs `tasks.md`) from lite (`harness-implement-lite`,
needs a real `verify:`, no `tasks.md`), so a careful agent stops blocking lite
execution over a missing `tasks.md`.

## How to apply

1. **Scripts are generated, not team-edited — overwrite in place.** Copy
   `assets/scripts/{speckit_gate.py,check_plan_coverage.py,wt_fanout.sh}` over
   `scripts/harness/`, `chmod +x`. Run all three selftests and report PASS/FAIL:

       python3 scripts/harness/check_plan_coverage.py --selftest
       python3 scripts/harness/speckit_gate.py selftest
       bash scripts/harness/wt_fanout.sh --selftest

2. **BREAKING — `scripts/harness/` now needs `covers:`.** Nothing to edit; be
   aware that this upgrade's own commit will be rejected by the sensor unless
   an active plan covers `scripts/harness/`. Commit it with
   `HARNESS_BYPASS="harness upgrade 3.0.0" git commit ...`.

3. **BREAKING — confirm before applying.** These may have been hand-edited
   since scaffold; show a diff and require explicit `y/n` per file:
   - `AGENTS.md` — two new hard constraints (clarify re-approval, skipping
     `/speckit-implement`'s setup step), Execute split into full/lite, a new
     "not closed until `status: completed`" gate, and the completion line now
     pointing at `closeout`.
   - `docs/processes/harness.md` — new § Two Execute modes, § Overrides of
     generated spec-kit steps; workflow table gains a Close out row; Loop
     Termination, Phase Gates, and Session Exit mention `closeout`.
   - `docs/processes/speckit-loop.md` — new § Lite Path and § Close Out.
   - `docs/PLANS.md`, `docs/processes/dev-setup.md` — the always-allowed list
     no longer includes `scripts/harness/`; `dev-setup.md` also gains
     `wt_fanout.sh --selftest` and the `doctor` command.
   - `docs/decisions/speckit-harness-integration.md` — § Feature resolution
     precedence amended; four new Consequences bullets.

4. **Merge into `.specify/extensions.yml` by hand** (the harness never
   clobbers it): `before_plan`'s prompt gains the post-clarify approval stop,
   and `before_implement`'s description/prompt now distinguish full from lite
   so a missing `tasks.md` does not block the lite path. Copy the two `prompt:`
   values from `assets/extensions.yml`.

5. **Replace `.agents/skills/harness-loop/SKILL.md`** with the new asset — it
   now runs `closeout` on `stop-converged`.

6. **Add the missing scaffold `.gitignore` entry if absent** (a 1.0.0 scaffold
   step that no version file ever carried, so some repos never got it):
   `specs/**/.loop-state.json`. `doctor` checks all five entries.

7. **Run `python3 scripts/harness/speckit_gate.py doctor`.** Fix every FAIL —
   this is the first upgrade that can tell you the previous ones did not fully
   land. Advance `.harness-version` to `3.0.0` **only on PASS**, except for
   `pre-commit-wired: FAIL` under a YAML/JSON hook manager, which stays a
   `docs/HARNESS-TODO.md` item.

## Removed

- `scripts/harness/tasks_to_issues.sh` — retired in 2.0.0; now enforced via
  `RETIRED_FILES` in `speckit_gate.py`, because repos recorded 2.0.0 without
  deleting it.
